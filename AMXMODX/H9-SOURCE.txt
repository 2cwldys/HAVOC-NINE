A git checkout of that commit. H9's changes are uncommitted working-tree changes against it (git status
and git diff show them), so they can be reviewed and committed as one set, and an update to a newer
goldsrc-net commit takes them along. It replaces the alliedmodders master tree H9 carried before
(2026-11-02; kept with its two H9 commits in TSM\backups\AMXMODX-alliedmodders-20261102).

Why this tree: the AMX Mod X H9 ships ("1.10.0-manual", from the reTS release) is this fork. Its core
reads the "gamedll_export" condition in a gamedata file's #supported block, which H9's gamedata needs to
pick reTS's offsets and drop TS 3.0's on reTS. alliedmodders master has no such condition.

TSX and reTS
------------
This fork's TSX reads TS 3.0's members through the gamedata above, which applies only to TS 3.0's own
library ("!ReTS_GetInterface"): reTS keeps that state at other offsets, or computes it. reTS exports
ReTS_GetInterface (reTS\dlls\rets_api.h), a table of get/set functions for every field TSX touches,
and H9's backend (change 5) uses it whenever the game library exports it: cash, free slots and the
move speed that follows them, ammo reserves and stack counts, the status message, powerups, slow
motion, the bullet trail, kung fu and superjump, the powerup pickup, the thrown knife's thrower. A
function a reTS leaves NULL refuses its native ("Native %s is not supported by this reTS").

Free slots on reTS are derived from the arsenal (plus what ts_setuserslots set), the grenade and
knife stacks included, so ts_setuserammo on a stack sets its count and only updates the move speed;
on TS 3.0 it moves the slot counter itself, as before.

It replaces reTSX, the tsx_amxx.dll the reTS release ships, whose own reTS backend is in no branch or
commit of this repository (docs\PLAYER_LIMIT_128.txt, section 8.5).

Building on Windows (H9's PC: Visual Studio 2026, no AMBuild)
-------------------------------------------------------------
Each <project>\msvc12\*.vcxproj with /p:PlatformToolset=v145 /p:Platform=Win32 and
/p:Configuration=Release (the core: JITRelease), from a copy of this tree, with the environment the
projects read:
  NASM_PATH  D:\msys64\mingw32\bin\  (the core's JIT, *.asm)
  HLSDK      goldsrc-net/hlsdk, branch 64bit: the SDK this fork's CI builds with
             (.github\workflows\build-release.yml); an older HL SDK clashes with public\resdk
  METAMOD    alliedmodders/metamod-hl1, the CI's too (metamod\meta_api.h)
The msvc12 projects lag AMBuild's (the AMBuilder files), so the copy's projects are set as those:
  * sources: the core's sm_crc32.cpp, hamsandwich's hook_signatures.cpp and Trampolines.cpp;
  * HAVE_STDINT_H defined (fun, tsfun and tsx lack it, and int32_t clashes with stdint.h);
  * default struct packing: engine, nvault, sqlite and tsx set /Zp4, which the Windows SDK's
    winnt.h (10.0.26100) refuses.
mysqlx also links MySQL's C connector from a mysql-5.5 folder beside the tree (the CI downloads
mysql-connector-c 6.1.1).
H9's build of 2026-11-02: hlsdk dd2c6d61, metamod-hl1 18a10db6; every project H9 ships but mysqlx.
