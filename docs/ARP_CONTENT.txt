ARP CONTENT ON HAVOC 9 -- the jobs, items, shops and NPCs of h9_tsrp_hive and h9_tsrp_newbyzantium
====================================================================================================

  Apollo RP builds every menu from content (docs\APOLLO_RP.txt, section 2). This is the content of H9's two roleplay
  maps: the Ministry of Defense ranks as jobs, the Insurrection's ranks, a civilian layer, and the NPCs that open the shops, the banks, the
  ATMs, the doctors and the gun shops, standing where section 6 puts them. Nothing here has been run in a game yet
  (section 8).


1. WHAT IS IN IT
----------------

  Per map, in apollo-rp\base\addons\amxmodx\configs\arp\maps\<map>\:
    <map>.sql   the jobs (40 rows of INSERT OR IGNORE INTO arp_jobs) and the properties and doors (section 9). ARP runs it by itself at every start of the map (section 2).
    npcs.ini    the NPCs: ARP_NPCs reads it when the map loads (hive: 24 NPCs, New Byzantium: 32).
    zones.ini   the zones: ARP_Zones reads it when the map loads, and the HUD's Location line names the zone the player stands in (hive: Alexandria, Paradise City, Xenon City; New Byzantium: New Byzantium; section 7).
    arp.ini     (already there) arp_table_jobs "arp_jobs_<map>": the jobs are the map's own, in their own table.
    pay.ini     what a job is paid in place of what its row says: ARP_PayScale reads it when the map loads (section 3). It says "Unemployed" 0 and lists every other job as a comment.
    propclip.ini  (the hive only) the invisible solid boxes that ARP_PropClip puts on the four bookshelves and bookcases the map left walk-through (docs\APOLLO_RP.txt, section 12).

  The items themselves are not content: ARP's plugins register all 95 of them in code (section 5). What the content
  decides is which NPC sells which item for how much, and which jobs there are.


2. HOW IT LOADS
---------------

  Nothing to do by hand. ARP_Core runs the map's .sql itself at every start of that map: after it has made its tables and before it
  reads the jobs, properties and doors, so the rows are there in the same map load, with no admin step and no reload. The file is
  configs\arp\maps\<map>\<map>.sql of the map that is loading. Its statements run in the file's order (so the jobs come in that
  order, JOBID 1 on in arp_joblist), each on the map's own table: the file says arp_jobs and the statement runs on arp_jobs_<map>.
  The log has one line for each start: [ARP] map SQL: N statements, 0 errors, jobs now 40, properties now P, doors now D (the hive: 390, 131 and 224 on a database that has
  the jail's property and its four doors; New Byzantium: 149, 30 and 93). A
  statement SQLite refuses is counted and logged (line L failed: ...) and the others still run. Players are told nothing.

  THE RULE for a file to be run by itself. A file that breaks any part of it is not run at all, not even in part, and the log says
  which line and why:
    * SQLite (arp_sql_type "sqlite", H9's), and arp_mapsql_autoload not 0 (configs\arp\arp.cfg). ARP_Core reads that file's line
      itself, because the server executes arp.cfg only after the core has started; when arp.cfg does not name the cvar, its value
      as it stands counts.
    * One statement to a line, a line of at most 1000 characters, at most 4000 statements. Blanks at either end of a line are
      ignored. An empty line, a line under 3 characters and a line that starts with - ; or # are skipped (the lines arp_config skips).
    * Each statement is exactly   INSERT OR IGNORE INTO <table> VALUES (...);   with one space between the words (the keywords in
      any case) and <table> one of arp_jobs, arp_property, arp_doors in lower case: the default names, which ARP swaps for the
      map's own (arp_jobs_<map> when the map's arp.ini names one, as H9's two do, else arp_jobs; arp_property_<map>; arp_doors_<map>).
      So: no other table, no column list, no INSERT ... SELECT, no CREATE TABLE (the core has made the tables), no UPDATE, DELETE or DROP.
    * The name of any of ARP's tables (arp_users, arp_jobs, arp_property, arp_doors, arp_keys, arp_items, arp_data) occurs once in
      the statement, as <table>: not inside a text and not a second time.
    * Nothing after the statement but its closing ; (which may be left off). Outside a 'text' no other ;, no -- or /*, no " or `.
      Every ' is closed (a '' inside a text is a quote); a text may hold ; and -- and the like.
    * Write the file in plain ASCII.
  The columns, in the order VALUES takes them:  arp_jobs (name, salary, access letters);  arp_property (internalname, externalname,
  ownername, ownerauth, price, locked, access, profit);  arp_doors (targetname as t|<targetname> or e|<entity number>, internalname).

  WHAT A START DOES. INSERT OR IGNORE adds a row when the table has none with the same key (jobs: name; properties: internalname;
  doors: targetname; the core makes each of the three tables with that key UNIQUE) and does nothing otherwise. So a start adds only
  the rows a table does not have yet and changes nothing else: a row an admin edited keeps the edit, a job added by hand stays, a
  property that has an owner keeps him. The rows a table already has keep their place and new rows follow them, so a job's number
  (JOBID) does not change under a player; a player's saved job is a name, found again in the map's table when he joins.
  (Checked on a copy of the live database: two starts give 26 rows with 0 errors each time.)

  A NEW INSTALL. The client package carries no database: stage-h9xash leaves data\sqlite3 (Apollo RP's arp.sq3) and any .sq3, .sqlite
  or .db file out and ships the folder empty, and H9XASH-Updater never touches them. A new player's first start of a roleplay map
  makes arp.sq3 and the map's tables, and runs the map's SQL file into them: the default jobs, properties and doors, with no
  player, bank or inventory in them.

  BY HAND. A file the rule refuses (the upstream maps' files are plain INSERTs), arp_mapsql_autoload 0 and a MySQL server (which
  needs  INSERT IGNORE  where the file says  INSERT OR IGNORE ) keep the old way. Back up data\sqlite3\arp.sq3 with the server stopped
  (docs\APOLLO_RP.txt, section 4), join as an ARP admin (access letter z) on THAT map, open the console and type  arp_config  ->
  3. Load Map SQL Data. The menu opens for an ARP admin and for an AMX Mod X admin with the ban flag; the latter makes himself an ARP
  admin first with 1. Add First ARP Admin. The screen shows "N/26 Completed - 0 Errors" and then "Map SQL loading is complete". The
  file loaded is the one named for the map you are on. That way sends every line as it stands, the default table names swapped for
  the map's own, and the rows are read at the next map start (restart the map).
  The NPCs need no loading: npcs.ini is read at every map start, so a change to it shows after the map restarts.


3. THE JOBS
-----------

  so a salary of 10 is 10 a minute and 600 an hour. The "$/hr" of the HUD and /menu, the "$/h" of the employ offer and the "m" of "Payday: 12m" (the passes left) are upstream's wording for
  that. New characters start with $500 in the wallet (arp_startmoney; the HUD's Credits line) and Unemployed pays 0, so that a character has to take a job to be paid. JOBID is the row order,
  which is the order the file inserts: lowest rank first.

    a  police     arp_police_access. Cuffs, the jail menu and panels, the door breakers (Steel Axe, Door C2), /com; a cop cannot be tazered or cuffed.
    b  medical    arp_medical_access. Counted as medical by ARP_IsMed (the /911 call reaches it).

                  (arp_teamplay 1) and shows as Insurgency on the look-at plaque. No job right holds it.
    j k l m       the Insurrection's hiring tiers, as c d e f are the Ministry's: j the junior ranks, k the NCOs, l the officers, m the high command.
    n             the Liberator's own, as g is the Lord Minister's: no job right holds it, so only an admin can offer the job (section 4).
  The M- ranks are the Medical Division: b and no a, the same salary as the rank beside them. From Captain up the division is not
  named (the museum: medical designations are dropped around Captain), so Captain to Lord Minister hold both a and b.
  No rank holds z. A rank is a role in the roleplay and never an ARP admin; administration is the Administrator job (26), which an
  admin gives with arp_setjob and which nobody else can offer, since no job right holds z. Lord Minister is the same kind of job in
  that only an admin can give it (its letter g is held by no job right).
  The civilian layer has no letters. The jobs are a starting set: add more with arp_addjob (section 7).

  WHAT A JOB IS PAID (ARP_PayScale; apollo-rp\ORIGIN.txt, item 49). The salary of a row is the base. configs\arp\maps\<map>\pay.ini, read when the map loads, may name a job and give it another
  salary:   "Citizen" 12   (one job to a line, the name as arp_joblist lists it, a whole number from 0 to 100000000; a line that starts with ; is a comment). A line wins over the row, in a database
  that has the row already too (the file's INSERT OR IGNORE never changes a row), so a change of pay is one number and a map change, with no UPDATE and no SQL. Both maps' files say
  "Unemployed" 0 and list every other job as a comment with the salary of its row: remove the ; and change the number. Every salary, a line's too, is then paid at arp_h9_pay_percent per cent
  (arp.cfg ships 100; whole numbers rounded half up, 50 pays half, 0 nothing). The HUD, /menu, the employ offer and arp_joblist say the salary that is paid, and arp_h9_pay_dump (the server's
  console, or an ARP admin's) lists each job's row, its line and its pay. A name that is no job of the map is said once in the log and does nothing; a job that no line names is paid its row. The
  plugin never writes the database: the rows stay as the file made them. Unemployed is 0 in the file as well, so a new database has it at 0; a database that has the old row (5) is paid 0 by
  the line, and  arp_query UPDATE arp_jobs_h9_tsrp_hive SET salary=0 WHERE name='Unemployed'  makes its row say 0 too (stopped, or live: it applies after the map restarts).


4. HIRING, FIRING AND JOB RIGHTS
--------------------------------

  arp_setjob <player> <job>      ARP admins only (z). Sets the job at once. <job> is a name in quotes ("Enforcer 1") or the JOBID.
  arp_employ <player> <job>      Offers the job; the player accepts or declines. Allowed to an admin, or to anyone whose JOB RIGHT shares
                                 a letter with the job's access letters.
  arp_fire <player>              Sets the player Unemployed. Same rule: a job right that shares a letter with the player's job.
  arp_setjobright <player> <l>   ARP admins only. A player's job right is a set of letters kept on his character (arp_users.jobright),
                                 NOT taken from his job: set it when he is promoted and take it away when he is not (<l> = -  for none).
  The tiers make the Ministry hire from below. Give these job rights, and never a, b, g or z (a job right of a would let its holder offer
  every police job, and a job right of z or g would let its holder offer the Administrator or the Lord Minister):
    Sergeant 1, Sergeant 2, Lieutenant      c       can offer and take Cadet to Ensign and M-Cadet to M-Ensign
    Captain, Major                          cd      and Sergeant 1 to Lieutenant
    Guardian, Legate                        cde     and Captain, Major
    Lord Commander                          cdef    and Guardian, Legate, Lord Commander
    Lord Minister                           cdef    the same as a Lord Commander; the Lord Minister and the Administrator are an admin's to give
  The Insurrection hires from below the same way, with letters of its own. Give these job rights, and never i, n or a letter of the Ministry (a job right of i would let its holder
  offer every Insurrection job, and a right of n or of a, b, c, d, e, f, g or z the Liberator, a Ministry job or the Administrator):
    Squad Leader, Cell Leader, Section Leader   j       can offer and take Recruit to Partisan
    Colonel, Marshal                            jk      and Squad Leader to Section Leader
    Tribune, Strategist                         jkl     and Colonel, Marshal
    Hetman                                      jklm    and Tribune, Strategist, Hetman
    Liberator                                   jklm    the same as a Hetman; the Liberator and the Administrator are an admin's to give
  A right works on a job when they share a letter, and the two ladders share none: no Ministry right (c, cd, cde, cdef) can offer or take an Insurrection job, and no
  Insurrection right (j to jklm) a Ministry job, the Lord Minister or the Administrator. Checked by script against the maps' .sql files: the names are unique and none of the
  fourteen is inside another job's name or has another inside it, so every name finds its own job, and no property of either map carries a letter from i to n.
  A job whose name is inside another's (Cadet inside M-Cadet) is still the job you name: arp_employ <player> "Cadet" offers Cadet.
  That needs H9-arpcontent.patch (ARP_Commands: an exact name wins). Without it ARP answers "more than one job matching your input"
  for Cadet, Enforcer 1 to 3 and Ensign, and the JOBID works instead. The same patch (ARP_Core) stops a short name that matches
  three or more jobs ("Enforcer") from writing past the command's array.
  A character keeps the job he has on a map that does not offer it (docs\APOLLO_RP.txt, section 8): the Ministry ranks belong to
  these two maps only, and a visit elsewhere does not cost a rank.


5. ITEMS AND THE SHOPS
----------------------

  what using it does. There are 95, all registered in code, none by this content:
    33    ARP_Items (licences, smokes, lighters, tools, drinks, drugs, door breakers, cards, the tazer, chlorofoam, Tape and Rope)
    8     ARP_HungerMod (food)

    46    ARP_TS (33 guns, two of them H9's own, and 13 ammunition kinds)
  The full list, with the number arp_itemlist prints for each item, what using it does and which shops sell it, is docs\ARP_ITEMS.txt.
  Cuffs, Tape and Rope are items while arp_h9_restraints is 1 (arp.cfg; with 0 there are 92 and the shops' sell lines for the three say "BAD ITEM ID: Contact admin").
  Police cuff with /cuff and need no Cuffs; anyone else needs one (docs\APOLLO_RP.txt, ORIGIN.txt 38).
  A gun is an item: buying one puts it in /items, using it opens the attachment menu and gives the gun. An ammunition item, used with
  the matching gun in hand, refills it. TS's licence classes are in the gun's description: Non-Restricted needs a Permitted License,
  Restricted a Restricted License, Prohibited cannot be bought at a gun shop (AK-47, Barrett M82A1, M61 Grenade, M60E3, sawed-off, Contender).
  H9's own PPSh-41 and Laser Rifle are items too, Prohibited, so no arms dealer sells them: the Black Market does, with no licence asked

  server's h9_customweapons is 1: with 0, using the item gives it back and says so, and such a server should drop the two sell lines.

7. CHANGING IT
--------------

  A salary, the easy way: a line of the map's pay.ini (section 3),  "Captain" 90  , and a map change. It needs no SQL and changes a database that has the row already.
  A salary or an access string in the database itself (live, as an ARP admin in the console, on one line, with the map's real table name; it applies after the
  map restarts, and to a player after he reconnects):
      arp_query UPDATE arp_jobs_h9_tsrp_hive SET salary=90 WHERE name='Captain'
  Then make the file say the same, or a fresh database loads the old row: edit the number in <map>.sql. Editing the file alone changes
  nothing on a map that already has the row: the file's INSERT OR IGNORE, run at every map start, never overwrites a row.
  A new rank: arp_addjob "Warden" 55 ad   (name in quotes, salary, letters), or one more INSERT OR IGNORE line in the file. Put it in
  the file at the position you want (rows load in file order; a table that already has rows gets the new one after them). arp_addjob
  refuses a name that lies inside an existing job's name.
  A rank taken away: arp_deletejob "Name". Players in the job become Unemployed at once; a character saved with its name is
  Unemployed on the map (with the notice that his job is not offered here) and keeps the saved name until he takes another job.
  The optional M-Sergeant 1, M-Sergeant 2 and M-Lieutenant are in each file as comments: remove the leading "-- " and load again.
  To change a rank on one map only, change that map's file/table; the two maps do not share a jobs table. To share ranks, give both
  maps' arp.ini the same arp_table_jobs (docs\APOLLO_RP.txt, section 8).

  Move or add an NPC: stand where it should be and type arp_getinfo (ARP admin): it prints Origin and the view angles. Put the origin in
  npcs.ini (the player origin is 36 over the floor; ARP drops the NPC to the floor), and the angle you want it to face PLUS 180. Keep it
  off doors, 56 units of open floor round it, and off a spawn point. Copy a block of the same type, change what is different, end it
  with [END]. Restart the map. A sell line is  sell "Item_Name price"  (underscores for spaces; the name need only be unique in the
  item list); heal "price" is a doctor's; addgun "Gun_Name price 0|1|2" is a gun shop's; property "<internal name>" is the property a shop or a gun shop earns its share of every sale for (section 6):
  ARP_NPCs reads ANY line that holds the word property as that line (unless it holds name, type, model, angle, origin, sell, heal, addgun or zone, which win), so no other line of the block may hold the
  word, and the property's name must hold none of those nine words.
  A terminal with nothing to see (a Bank Terminal) is an NPC of type bank whose model is models/player/Invisible/invisible.mdl: its box is still 32 by 32 by 72, so it stops a player and the crosshair finds it
  (a bank's name must hold the word bank).
  A new KIND of item (a Ministry ID, a ration pack) needs a plugin: ARP_RegisterItem in ARP_Items.sma or one of its siblings, with a
  handler. A shop can only stock what is registered.
  On h9_tsrp_hive an NPC belongs in a named place (the table's last column): a shop, a bar, a clinic hall or a post. Move it inside that place, beside the counter it stands at and
  facing the way customers come in; keep the origin off a door (the back doors of these shops never open), off a start point, 40 from a bot waypoint, with a floor in front of it that a
  player can stand on within about 90 units of its box (ARP's use takes the NPC a player aims at within 100 units of his eye) and that joins the walked floor. The spots are proved against
  the hive's own .map (H9XASH\ts\maps\h9_tsrp_hive.map) with the doors as the game has them: a func_door whose name nothing fires and that does not start open is shut (209 names), so a room
  behind one is not a place for an NPC. The compiled map is BSP2, which SMAK cannot read; the cities' own compiles (v30) show the places with their textures and light.
  On h9_tsrp_newbyzantium an NPC belongs in a room: a shop's door is a rolling shutter (texture garage03), a bar's a pair of wooden doors (cds_wooddoor1),
  a clinic's a lab door (cds_labdoor1). Stand inside, beside the counter and facing the door, and keep the origin 52 from every door, off a start point,
  with 56 to 110 units of floor in front of it that a player can stand on, and the floor round it still walkable (two NPCs of a room 72 apart at least).
  The map the spots are proved against is the shipped H9XASH\ts\maps\h9_tsrp_newbyzantium.bsp, not the .map in export-map\h9_tsrp_newbyzantium\out: that
  .map is a later generation whose rooms are elsewhere. If the city is compiled again, every shop moves and each NPC has to be placed again.
  Change a zone (the HUD's Location line says "Location: <zone>", and "Unknown" when the player has none): edit zones.ini of the map and change the map. A zone is its name on a line, then a block in braces with the two
  corners of a box, "boundaries1" "x y z" and "boundaries2" "x y z", in any order; a comment starts with ; in column 0, and only comments may stand between a name and its opening brace. Once a second ARP_Zones compares each
  player's origin with every zone but his own and takes the first box that holds it (strict inequalities); he keeps that zone until he enters another one. So the boxes must not overlap (a player in two of them would flip
  between them every second), and a point in none leaves him in his last zone. h9_tsrp_hive has three, 9000 each way sideways (the world is x -3968 to 3792, y -4036 to 4040, z -4040 to 4040): Alexandria (z up to -1488),
  Paradise City (-1488 to 411) and Xenon City (411 up). The planes -1488 and 411 are the middles of the two caps, 8 units thick, with which the map stacks its three cities: solid at every point of a 32-unit grid over the whole
  map. No standing player's origin is possible anywhere between z -1528 and -1450 or between 371 and 449 (the clip hull of the compiled map has no free point on a 16-unit grid on any plane, in steps of 2, in those
  ranges; the nearest heights it allows are -1530 and -1448, 369 and 451), so every floor, ladder, lift and travel zone of a city is on its own side.
  h9_tsrp_newbyzantium has one zone, New Byzantium, over the whole map. A trigger_multiple with a targetname that a player touches would set the zone to that name for up to a second;
  neither map has one (the hive's two trigger_multiple, the Tartec front door and the bank door, have no targetname, and New Byzantium has none).
  ARP_Zones as Apollo RP ships it has two faults, which arp_h9_zonefix 1 (the default; 0 is the stock plugin) repairs. It stops with a memory access error at the end of the first zone of a zones.ini (the trie wrapper it calls
  writes the end of a string one cell past a 4-cell buffer, and AMX Mod X puts the terminator there), so a file of several zones gave its first and a player outside it read Unknown. And its touch handler returns
  FMRES_IGNORED, which is 1, and a touch handler's 1 blocks the touch, so a player's touch of ANY trigger_multiple did nothing: the hive's two automatic doors (the Tartec front doors and the bank's glass doors, each opened
  by such a trigger) stayed shut. The zones are read from the line of arp.cfg when the map loads, so a change takes a map change; the touch follows the cvar and is read at every touch.
  A prop a player walks through (a ts_model: a bookcase, a couch, a table): add its line to the map's propclip.ini, which only the hive has so far. python tools\propclip_tool.py lines <map> --model
  "<part of the model's name>" prints the lines (docs\APOLLO_RP.txt, section 12); for New Byzantium python tools\propclip_tool.py write h9_tsrp_newbyzantium --model "<part of the name>" --out <the
  file> makes the file, and the file goes in its folder of configs\arp\maps.
  The H9 content files are written by the tools that placed the NPCs; edit the files by hand from here on.

9. PROPERTIES AND DOORS (what the look-at plaque names)
------------------------------------------------------

  A property is a building or a place: a name, an owner or none, a price, a lock and access letters. Its doors are the map's func_door entities,
  bound to it by their targetname in the table arp_doors, one row for each door, as many as its building has. The look-at plaque (docs\APOLLO_RP.txt,
  section 2) names the property of the door a player looks at: the external name as its heading, OWNER (the owner's name, with his job while he is in
  the game; STATE PROPERTY when there is no owner and no price; FOR SALE and the price when there is a price), AFFILIATION, STATUS (SEALED when the
  property is locked, OPEN when not) and a RESTRICTED line when the player may not use the door. Both maps' .sql files carry the rows (section 2 says
  how they are loaded): the hive 130 properties with 220 door names, New Byzantium 30 with 93.

  THE FIELDS (the order VALUES takes them in arp_property): internalname (a slug, h9_<city>_<thing>), externalname (at most 32 characters, what the plaque shows),
  ownername and ownerauth (both empty: no owner), price (0: not for sale), locked (0 or 1), access (letters), profit (0; the NPCs of npcs.ini that name this property
  add a quarter of each sale to it, and /profit pays it to the owner; nine of the hive's shops name one: section 6).

  AFFILIATION is read from the access letters, and is documented here because the plaque asks for it: the police letter (arp_police_access, a) or g
  (the Lord Minister's own, which only that job holds) is the MINISTRY OF DEFENSE; the medical letter (arp_medical_access, b) is the MEDICAL
  DIVISION; a property with both says both ("Ministry of Defense / Medical Division"); the admin letter alone is ADMINISTRATION; no letter is
  CIVILIAN (PROLETARIAN while arp_teamplay's team play runs). The plaque of a player reads the same letters from his job (docs\ARP_CONTENT.txt, section 3: a Cadet to a Lord Commander are Ministry of
  Defense, the M- ranks Medical Division, a Merchant Civilian). The c d e f letters are hiring tiers and open no door, so no property uses them.

  ALL THE DOORS OF A BUILDING. A property is the whole establishment: every named door of its building is bound to it (front, back, side, staff,
  office, store room, roof, bathroom, stair and inner doors), and all of them show the same plaque and obey the same lock, because the lock is the
  property's (below). The hive's doors were taken from the compiled map the game loads (H9XASH\ts\maps\h9_tsrp_hive.bsp: 294 door entities with 277
  names, every one of them named; 293 and 276 after the clandestine vent was made a breakable) by where each door stands, by the closed rooms the map's space model makes when every door is shut (doors that open
  into one closed set of rooms belong to one building), by the sign that hangs by a door and by the pattern of the names (pc_ Paradise City, xe_
  Xenon City, al_ Alexandria; unclepikky, enzos, cp_, skyb, golgo, midgar and so on). Three rules hold for every row: a door is bound only if it is a
  named door of the BSP; no door is in two properties; and a name that two doors of different buildings wear is not bound, because a door row binds
  by name and would take both. Where a building's doors might belong to two establishments the map does not tell apart, neither is guessed: the doors
  are left out and listed below.

  LOCKED and the access letters. A named func_door does not open when it is touched. ARP's touch hook forces a use on an unlocked property door, so
  anyone who touches it toggles it, and blocks a locked one; ARP's use key opens a locked door for its owner, a key holder or a player who shares a
  letter with the property's access. So locked 1 leaves every door as the map made it, and only the owner, a key holder or the access letters use it.
  The lock belongs to the PROPERTY, never to a door: all the doors of a property are locked, or none is. The rows follow one rule: a door the map
  starts open on a public establishment (a front door, spawnflags bit 1) is unlocked, and its plaque says OPEN; every other door is locked and says
  SEALED. So a shop whose front door starts open and whose back, side or staff door is shut is two properties with one plaque heading (h9_pc_pikkys
  and h9_pc_pikkys_back): the front one unlocked, the one of the shut doors locked. A home, and a business for sale, is locked whole until somebody
  buys it, whatever its doors start as; a locked door that starts open (a flat's door, a club's gate) stays open as the map has it, and its plaque
  still says SEALED. Two properties are unlocked although their doors do not start open: the Paradise bank's glass doors and Tartec's front doors,
  which a trigger of their own opens. ARP's lock cannot take the use key from the game's own handling of a door that has the use-only flag
  (spawnflags 256: every named door of New Byzantium and the Midgar Office's two car doors); the plaque says what ARP holds.

  PRICES are one geometric scale, the scale of the first file (round(1200 * 2^tier), to two significant figures) times 3, to two significant figures again (PRICE_MULTIPLIER in tools\gen_prices.py),
  tier 0 to 5: 3,600  7,200  14,000  29,000  57,000  110,000. Every tier is twice the one before, within the rounding. The base, 3,600, is 6 hours of a Citizen's pay (docs\ARP_CONTENT.txt, section
  3: a Citizen 10 a minute, paid every 60 seconds, so 600 an hour; a Merchant's hour is 1,200) and is what the smallest property costs. The dearest, 110,000, is 12.2 hours of a Lord Minister's pay
  (150 a minute, 9,000 an hour) and 18.3 of a Legate's (100 a minute): a rank that has served a while can buy it; a Citizen needs 183 hours of pay. The property tax costs the owner 0.1 percent of
  the price every 15 minutes (0.4 percent an hour, arp_h9_tax_percent; he pays it by hand with /renew, or it is taken from his bank with arp_h9_tax_manual 0): tier 0 costs 16 an hour (3 percent of a
  Citizen's pay), tier 3 (29,000) 116 (10 percent of a Merchant's), tier 5 440 (5 percent of a Lord Minister's). A property's tier is its kind's base plus a step for its floor area, plus 1 when it
  has four or more doors, at most 5:
    kind base:   stall (a storage unit, a stash) 0 and pod 0 (a pod or a stall is tier 0 whatever its size: one small room);  a flat, a house, an apartment 1;
                 a workroom (an office, a hideout, a vault, a plant) 1;  a luxury residence 2;  a shop, a cafe, a bar, a club, a restaurant, a distillery 2
                 Every property but the state properties is for sale, so the rows that began as state or public ones are priced the same way: a shop, a bank, a clinic or a corporation's front is a business; the back,
                 side and staff doors of a shop, a clinic's gate, an office, a lab, a vault and a store room are workrooms (their rooms are the front's, one kind lower). A state property is not priced and nobody can
                 buy it: the guard posts, the throne room, the buildings of the Ministry of Defense and the MSR gate, sealed to their letter, and the ways through that a whole city uses (the level doors, the
                 underground gates, the lift, the core console, Tartec's glass doors), open to everyone, so that no buyer's lock can shut them.
    area step:   under 60k square units of closed floor behind the doors 0;  60k to 150k 1;  150k to 250k 2;  250k and over 3;  not measured (the room behind the door could not be closed
                 by the flood fill of the room analysis) 1, the middle step
  The floor area is the closed rooms behind a property's doors (the room analysis of the plaque work, 16 x 16 unit cells; the work folder's rooms_complexes.json), in thousands of square units.
