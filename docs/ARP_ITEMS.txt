ARP ITEMS: THE CATALOGUE OF H9'S APOLLO RP
==========================================

  Every item a character can carry on H9's two roleplay maps (h9_tsrp_hive and h9_tsrp_newbyzantium): its number, its name, what the game's own list prints for it, what
  using it does, and which shop sells it for how much. There are 95 (92 with arp_h9_restraints 0). docs\ARP_CONTENT.txt, section 5, has the counts and the shops in prose;
  this file is the catalogue.
  The tables are written by tools\gen_items.py from the plugins' sources and the two npcs.ini files, and tools\check_items.py compares them with what the game prints
  (arp_itemlist) and with docs\ARP_CONTENT.txt (section 12 says how to run both). Apollo RP's ARP_BCompat, ARP_CS and ARP_TFC register items for other games; H9 does not
  run them and they are not here.

1. LISTING ITEMS IN THE GAME, AND WHAT THE NUMBER IS
----------------------------------------------------

  In the game's console (the ~ key) any player can type

      arp_itemlist          items 1 to 30
      arp_itemlist 30       items 31 to 60
      arp_itemlist 60       items 61 to 90
      arp_itemlist 90       items 91 to the last

  It is a command of a player's own console: it prints there, and the server's console does not know it ("Unknown command"). A page is arp_items_per_page items (30). The
  number after the command is the last item of the page before, and every page that is not the last ends with the command for the next one. A number past the last item
  answers "No jobs to display at this area." (the core reuses the job list's words). A line reads

      #<number>   <name>   <Yes or No>   <description>

  Yes is the item's disposable flag. The description is cut to 63 characters, as the core stores it. A player's own items: say /items (an H9 client opens the inventory
  window).

  THE NUMBER is the item's id. The core counts the calls of ARP_RegisterItem from 1 each time a map loads: ARP_Core runs the forward ARP_RegisterItems once, in its
  precache, and AMX Mod X calls the plugins in the order of configs\plugins.ini, so the number follows the plugin order and, inside a plugin, the order of its calls. The
  order this file uses is H9's (plugins.ini's, with ARP_PayScale, ARP_H9Ctx, ARP_PropClip last, where build.bat appends it):

      ARP_Core, ARP_Commands, ARP_Config, ARP_HUD, ARP_HungerMod, ARP_Items, ARP_JailMod, ARP_NPCs, ARP_RobMod, ARP_TalkArea, ARP_Zones, ARP_TS, ARP_H9Menu,
      ARP_Inventory, ARP_PropertyTax, ARP_PayScale, ARP_H9Ctx, ARP_PropClip

  Five of them register items (ARP_PayScale and the others do not): ARP_HungerMod 1 to 8, ARP_Items 9 to 41, ARP_JailMod 42, ARP_TalkArea 43 to 49, ARP_TS 50 to 95.
  Moving a plugin in plugins.ini, a new plugin that registers items or a new item in one renumbers what follows. A character's items are kept by name (the table arp_items
  holds "<character key>|<item name>"), so a renumbering moves nobody's things; but a number typed into arp_createitems, or noted down, then means another item.

  arp_h9_restraints (configs\arp\arp.cfg, 1 as shipped) decides whether Tape (39), Rope (40) and Cuffs (42) exist; ARP_Items and ARP_JailMod read it from arp.cfg when the
  items are registered, so a change needs a map change. With 0 there are 92 items: those before Assassin Knife (41) keep their numbers, and a later one is lower by the
  number of those missing before it (from Assassin Knife (41) on, 2 lower; from Motorola RAZR (43) on, 3 lower). Both numbers are in the tables: NO is the number with the
  shipped 1, R0 the number with 0.


2. GIVING AN ITEM (ADMINS)
--------------------------

  An ARP admin (docs\ARP_ADMINS.txt, section 8) gives items from the server's console or from his own:

      arp_createitems "<player>" "<item name or part of it>" <n>
      arp_createitems "<player>" <number> <n>

  The item is a number from this file or a part of a name, in any case. A part that fits two items is refused ("Found more than one item with that name."): "Lighter" (it
  is in "Zippo Lighter"), "Lockpick" (it is in "Electric Lockpick"), "Gin" (it is in "Taurus Raging Bull"), "Bug" (it is in "Bug Scanner"). So is any other part that two
  names hold, such as "GLOCK" or "Ammo"; say more of the name, or give the number. arp_removeitems and arp_setitems take the same arguments (docs\ARP_COMMANDS.txt, 6).


3. HOW TO READ THE TABLES
-------------------------

  Each plugin has a list table (what the game prints, with the numbers) and a table of what its items do and where they are sold; the ARP_TS section has a third, of its
  guns.

    NO            the number with arp_h9_restraints 1, as shipped.  R0: the number with 0; "-" for an item that does not exist then.
    NAME          as the list prints it.
    DISP          Yes: the core takes one away after the item's handler has run. No: it stays, unless the handler takes one itself (each line says).
    CUT           "cut" where the stored description is longer than the 63 characters the list prints; the whole text is in the next table.
    DESCRIPTION   as the list prints it, spelling and all.
    NOTE          what is special about the item.
    SOLD BY       the shop role and its price in credits. A role is one stock: every NPC of a role, on both maps, sells the same things at the same prices (section 9 names the NPCs).
                  "not sold by any NPC": no shop line, gun shop line or bank menu names the item. An admin gives it (arp_createitems), or players hand it on.
                  A gun shop's price comes with the licence its menu asks for; a shop (the Black Market too) asks for none.

11. ODD THINGS THE CODE DOES
----------------------------

  - Chlorofoam (38) is sold for $400 and has no handler: ARP_Items registers "_Chlorofoam" and defines no function of that name, so using it does nothing at all: the
    core finds no function to run, tells the player nothing and leaves the item in his hands.
  - Phone Subscription (46) and Phone Prepaid Card (47) are never read: calls need neither, and a character with one has nothing more than one without.
  - H&K MP7 (65): the description says 4.6mm, but the ammunition it takes is 5.7mm FN Ammo.
  - U.S. Ordnance M60E3 (76): the description says 7.62mm (NATO), but the ammunition it takes is 5.56mm NATO Ammo.
  - PPSh-41 (81) and Laser Rifle (82): no ammunition item refills them (their ammunition type in ARP_TS is 0).
  - The description of Combat Knife (71) and Mossberg 500 (72) spells the class "Non-Restriced"; the list prints it so.
  - DISP says No for the First Aid Kit, the Spray Can, Tape and Cuffs, which the handler (or, for the Spray Can, the spray key) still takes away, and for the Lockpick
    (it can snap) and the Tazer (it can short-circuit): the column is only what the core does after the handler has run.


12. KEEPING THIS FILE TRUE
--------------------------

  The tables are not typed: tools\gen_items.py rebuilds them from the plugins' sources (the five plugins above, ARP_NPCs, the two npcs.ini files, plugins.ini and
  build.bat for the order, tsconst.inc and ApolloRP_TS.inc for the TS weapons). After an item, a plugin's order, a shop line or a price changes (an NPC whose name no role
  knows stops the generator and says which: one line in ROLE_OF of gen_items.py gives it its role):

      python tools\gen_items.py --doc docs\ARP_ITEMS.txt         writes this file again
      python tools\gen_items.py --facts                           checks the facts the "what it does" lines rest on against the plugins (171 patterns); one that fails names the line to read again
      python tools\check_items.py                                 this file against the sources, against docs\ARP_CONTENT.txt (section 5) and against arp_itemlist

  check_items.py reads a capture of arp_itemlist: run arp_itemlist, arp_itemlist 30, arp_itemlist 60 and arp_itemlist 90 in a game's console, save the text (the pages may
  be pasted one after the other) and give the file with --itemlist. With the shipped arp_h9_restraints it must show 95 items, and with 0, 92; every name, disposable flag
  and description must be the table's.
